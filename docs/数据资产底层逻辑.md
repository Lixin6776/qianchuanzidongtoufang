# 数据资产 · 底层逻辑

> 这份文档讲的是「数据资产」窗口背后**到底怎么算的**——数据从哪来、每一步怎么处理、
> 每个数字是什么口径、哪些结论能信、哪些不能信。
>
> 当前基线（2026-10-19）：资产年龄 11 天 · 盯盘 1,511 条 · 操作 593 笔 · 已下结论 3 类 · 24h 有效率 99%。

---

## 一、它回答什么、不回答什么

| 回答 | 不回答 |
|---|---|
| 本账户**哪些操作**被数据正向反馈 | 「这个操作是不是**因果**导致的」（观察性） |
| **在什么流速下**操作更有效 | 别的账户/别人适不适用（账户特定） |
| 这些结论**有没有变稳**（趋势） | 未来一定怎么走（不是预测模型） |
| 每笔操作的**原始凭证** | 自动帮你改账户（只读） |

**一句话定位**：它是一本**会自己算账的运营账本**，不是"AI 帮你做决定"。

## 二、数据流（四层）

```
① 原始事实层
   每 5 分钟盯盘记录（spend/gmv/roi/cpm/在线/基础追投拆分…）
   千川平台操作日志（你手动做的操作）
         │
         ▼
② 结构化层
   操作被归类：暂停追投 / 加追投预算 / 降追投预算 / 新建追投 / 加素材 / 一键起量…
   每条操作带：时间、类型、对象、原始文本
         │
         ▼
③ 判断层
   边际 ROI → 扣基线漂移 → 净效应 → 按流速分层 → 样本护栏
         │
         ▼
④ 应用层
   回流进「盯盘报表」的历史账本
   回流进「直播复盘」的历史账本
   在「数据资产」窗口展示 + 每日快照 + 流水导出
```

## 三、数据模型（字段级）

### 3.1 盯盘记录（每条 5 分钟）

| 字段 | 用途 |
|---|---|
| `created_at` | 时间锚点（所有窗口计算的基础） |
| `source` | `cdp` = 有效读数；`cdp-error` = 读取失败（**不参与计算**） |
| `spend` / `gmv` | **场次累计值**（不是窗口值） |
| `roi` / `gpm` / `cpm` / 在线 / 观看 | 辅助指标 |
| `spend_split` | 基础 / 追投拆分（用于流速与结构） |
| `platform_operations` | 结构化平台操作日志（新增） |
| `report_markdown` | 老报告的兜底解析来源 |

### 3.2 操作（结构化）

从 `CdpPlanLogReader.parse_plan_log_text()` 得到：

```json
{
  "time": "2026-10-19 12:23:49",
  "type": "修改",
  "details": ["操作内容：素材追投，ID：…", "调控预算：3000.00元 -> 100.00元"],
  "summary": "操作内容：素材追投，ID：…；调控预算：3000.00元 -> 100.00元",
  "day": "2026-10-19"
}
```

## 四、核心算法（逐步）

### 4.1 为什么不直接用 `roi`

报表里的 `roi` / `spend` / `gmv` 是**场次累计值**。直接比"T 时刻 vs T+10 时刻的 ROI"，比的是
**整场累计**，会被前面的历史数据稀释——**看起来所有操作都无效**。

所以统一改成 **边际（窗口）ROI**：

```
窗口 ROI = (GMV_末 - GMV_初) / (SPEND_末 - SPEND_初)
```

> 保护：`SPEND_末 - SPEND_初 <= 50 元` 时算不出，直接丢弃（避免除以极小值）。

### 4.2 每个"时刻"的变化量

对每一条有效记录（时刻 `t`）：

```
pre_roi  = 窗口ROI(t-10min → t)
post_roi = 窗口ROI(t → t+10min)
delta    = post_roi - pre_roi
```

找 ±10 分钟的记录时，**容差 ±200 秒**（因为盯盘有抖动，不是精确 5 分钟）。

### 4.3 基线漂移（最关键的一步）

**实测：什么都不做，10 分钟后边际 ROI 也会掉约 -0.10。**

如果不扣掉它，**所有操作都会看起来是负的**（早期就踩过这个坑）。

```
对照组 = 前后 7 分钟内【没有任何操作】的时刻
基线   = median(对照组的 delta)
```

### 4.4 净效应

```
净效应 = median(操作组的 delta) - 基线
```

**这才是"这个操作相对'什么都不做'的好坏"**。

### 4.5 按操作类型归因（排除重叠）

实际操作经常**扎堆**（同一时刻暂停追投 + 加预算 + 加素材）。
如果把同一时刻的 delta 记给每种操作，**所有类型都会继承同一个效应**（实测会全部变成 positive）。

所以：

> **只统计「此刻只有一种操作」的样本**；多种操作同时发生的时刻，**不参与单类型归因**。

代价：`新建追投` 这类总爱跟别的操作一起做的类型，样本会很少（可能不足 20）→ 标"样本不足"。

### 4.6 按流速分层

同一批数据按流速（`(spend_t - spend_{t-10}) / 10 分钟`）三分位切档：

```
慢 / 中 / 快  三档
每档内：median(有操作) - median(无操作) = 该档净效应
```

**为什么必须分层**：实测聚合值是 +0.16（看起来"操作都有效"），
分层后是 **慢 -0.17 / 中 +0.31 / 快 +0.22** —— **聚合把关键规律掩盖了**。

### 4.7 判定规则

| 条件 | 判定 |
|---|---|
| `n < 20` | 样本不足（不给方向） |
| `净效应 > +0.10` | 正向 |
| `净效应 < -0.10` | 负向 |
| 其余 | 中性 |

> 阈值 0.10 是"可感知"的最小差距（ROI 小数点后两位），不是统计显著性检验。

## 五、操作分类规则（确定性，不用 LLM）

**先认"操作对象"，再认"改了什么"**（顺序很重要）：

| 文本特征 | 归类 |
|---|---|
| 含「素材追投」+ `调控状态 -> 已暂停 / 调控手动关闭` | 暂停追投 |
| 含「素材追投」+ `调控状态 -> 调控中` | 开启追投 |
| 含「素材追投」+ `调控预算 A -> B`，B>A | 加追投预算 |
| 含「素材追投」+ `调控预算 A -> B`，B<A | 降追投预算 |
| 含「素材追投」+ 类型=新建 + 有调控预算 | 新建追投 |
| 含「一键起量」 | 一键起量 |
| 含「搜索抢首屏」 | 抢首屏 |
| 含「成交出价」 | 出价调整 |
| 含「综合营销ROI目标」 | ROI目标调整 |
| 含「增加视频ID / 增加标题ID」 | 加素材 |
| 含「删除千川星选」 | 删素材 |
| 都不匹配 | 其他 |

> **踩过的坑**：早期先匹配"调控预算"，导致「**一键起量**的预算 7500→8000」被误归成「加追投预算」。
> 现在先判操作对象，已修复并加了回归测试。

## 六、常用参数（代码里的常量）

| 常量 | 值 | 含义 |
|---|---:|---|
| `MIN_SAMPLE` | 20 | 低于它不出结论 |
| `FORWARD_MINUTES` | 10 | 看操作后 10 分钟 |
| `OP_WINDOW_SECONDS` | 420（7 分钟） | 判定"此刻附近有操作"的时间窗 |
| `NEIGHBOR_TOLERANCE_SECONDS` | 200 | 找 ±10 分钟记录时的容差 |
| `KEEP_ROWS` | 20,000（约 70 天） | 盯盘记录保留量 |

## 七、质量护栏（每条都必须有）

1. **样本不足不出结论**（n < 20）；
2. **观察性相关，不是因果**（操作是你自己按状态选的）；
3. **排除重叠操作**（只做单操作归因）；
4. **扣基线漂移**（不扣会全错）；
5. **读失败不参与计算**（`cdp-error` 直接跳过）；
6. **数据断档时该窗口算不出**（`None`，不参与，不当成"无效"）；
7. **账户特定**（结论只对本账户成立，不外推）。

## 八、时间维度：每日快照

- 每天 **08:10**（等 08:00 素材、08:05 汇报落地后）自动存一份 `asset_snapshots.json`；
- **同一天只留一份**（后写覆盖），跨天各留一份；
- 用途：看**样本在不在长、结论在不在变**。

## 九、已知局限（必须承认）

| 局限 | 说明 |
|---|---|
| **观察性，非随机实验** | 操作是你自己选的，有选择偏差（已用"分层 + 对照"部分缓解） |
| **操作重叠** | 大部分操作扎堆，单操作可归因的样本偏少 |
| **账户特定** | 11 天、单一账户，不能外推到别人 |
| **历史已丢失** | 早期只保留 1500 条（约 5 天），被裁掉的部分无法恢复；现在改为 20000 条 |
| **窗口口径** | 只看 10 分钟；更长的效果（如素材衰退）需要更长窗口，暂未做 |

## 十一、一句话总结

> **数据资产 = 把「你做了什么」和「之后数据怎么变」记成账，扣掉账户本身的漂移，
> 再用对照组和分层算清楚——哪些动作在这个账户上真的有用、在什么状态下才有用。**
>
> 它给的是**证据**，不是**因果**；是**参考**，不是**命令**。
