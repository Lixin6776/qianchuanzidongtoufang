# 千川直播运营助手 MVP（客户版）

> 版本：0.1.0  
> 定位：**单客户、单账户、本地私有部署、只读优先**的直播运营工作台。  
> 目标：客户能自己安装、连接数据源、完成部署自检、看到当前直播问题，并跑出第一份可复盘的数据。

---

## 1. 这个 MVP 能做什么

- 直播盯盘：按场次读取 ROI、GPM、消耗、成交、在线人数等指标。
- 数据可信度提示：来源、新鲜度、字段完整度、场次是否确认。
- 最多 3 个优先问题，每个问题给出一个可执行动作和验证窗口。
- 运营任务：生成任务、10 / 30 分钟验证、失败回滚提醒。
- 投手知识库：上传 TXT、Markdown、CSV、JSON、YAML、PDF、Word；没有文件时回退本账户历史平均值。
- 直播复盘、素材分析、运营助手对话、数据资产沉淀。
- 系统自检：随时检查运行环境、数据库、存储、直播间配置、数据连接、首次报表等状态。
- 默认只读：不会自动修改预算、出价、计划或素材；写操作必须人工确认。

## 2. 这个 MVP 暂时不包含

- 云端账号、多租户、团队角色与权限。
- 在线计费、订阅、客户自助开通。
- 多账户并行管理。
- 云同步和手机 App。
- 无人值守自动投放。
- SaaS 级别的远程运维与集中监控。

如果需要多人、多账户、远程访问或商业计费，应在 MVP 验证通过后进入下一阶段，而不是直接在当前版本上叠加。

## 3. 客户电脑要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10/11 或 macOS |
| Python | 3.11 或更高 |
| Node.js / pnpm | 仅源码安装和重新构建前端时需要 |
| 浏览器 | Google Chrome |
| 网络 | 能访问千川后台；使用开放平台连接时需能访问巨量开放平台 API |
| 账户 | 一个千川广告账户；使用 API 时需完成应用授权 |

## 4. 全新电脑安装

### Windows

1. 从 GitHub 下载或克隆仓库：
   `https://github.com/Lixin6776/qianchuanzidongtoufang`
2. 双击 `安装依赖.cmd`。
3. 看到“全部完成”后，双击 `启动直播运营助手.cmd`。
4. 浏览器打开 `http://127.0.0.1:5173`。

### macOS

```bash
git clone https://github.com/Lixin6776/qianchuanzidongtoufang.git qianchuan-ai-assistant
cd qianchuan-ai-assistant
chmod +x 安装依赖-macOS.command 启动直播运营助手-macOS.command
./安装依赖-macOS.command
./启动直播运营助手-macOS.command
```

macOS 日常地址为 `http://127.0.0.1:8000`。完整说明见 `docs/Mac使用指南.md`。

## 5. 首次使用流程

1. 打开左侧 **数据源**。
2. 填写直播间名称和账户 ID（千川后台 URL 中 `aavid=` 后面的数字）。
3. 点击 **连接数据源**。首次弹出 Chrome 时登录一次千川。
4. 打开左侧 **系统自检**，点击 **重新自检**。
5. 自检没有“阻断”后，回到 **直播盯盘**，点击立即读取或开始盯盘。
6. 确认报表来源、数据时间、场次和指标完整。
7. 进入 **运营任务**，只处理优先问题中的动作；按 10 / 30 分钟验证结果。
8. 直播结束后停止盯盘，等待复盘生成；次日检查复盘和素材分析。

> 普通客户优先使用“本机浏览器连接”。开放平台连接属于更稳定的长期接入方式，需要 App ID、App Secret、广告主授权和 Token。

## 6. 系统自检怎么读

| 状态 | 含义 | 怎么处理 |
| --- | --- | --- |
| 通过 | 该项正常 | 无需操作 |
| 提醒 | 不阻断使用，但会影响完整体验 | 按按钮进入对应模块处理 |
| 阻断 | 当前无法正常交付或读取数据 | 必须先处理，再给客户使用 |

MVP 自检覆盖：

- Python、操作系统、应用版本。
- 前端构建产物是否完整。
- `.local` 数据目录是否可写。
- 本地 SQLite 数据库是否可读。
- 直播间名称和账户 ID 是否配置。
- 本机浏览器 / 开放平台连接是否可用。
- 千川页面是否打开、是否疑似未登录。
- 投手知识库状态。
- 盯盘是否运行或中断。
- 是否已有第一份盯盘报表。
- 大模型是否配置（可选）。

自检不会返回 Token、Secret、Cookie 或完整凭据。

## 7. 数据与备份

以下内容只保存在本机，不随 GitHub 仓库同步：

| 内容 | 位置 |
| --- | --- |
| 本机配置 | `.local/config.json`、`backend/.env` |
| 盯盘记录、复盘、知识库、运营对话 | `.local/` |
| 策略与数据库 | `backend/qianchuan.db` |
| 开放平台凭据 | `.local/api_config.json` |
| 大模型 Key | `.local/llm_config.json` |
| 千川登录态 | Chrome 用户目录 |

迁移电脑时，复制 `backend/.env`、`backend/qianchuan.db` 和整个 `.local/` 到新电脑对应位置。不要把这些文件提交到 GitHub。

## 8. 客户交付验收清单

在客户电脑上逐项确认：

- [ ] 安装脚本完成，无报错。
- [ ] `http://127.0.0.1:5173` 或 macOS 的 `http://127.0.0.1:8000` 可以打开。
- [ ] 系统自检没有阻断项。
- [ ] 直播间和账户 ID 正确。
- [ ] 数据源连接成功，千川已登录。
- [ ] 第一份报表能读到明确的数据时间、来源和场次。
- [ ] 报表没有伪造或静默填充缺失数据。
- [ ] 能生成一个运营任务并完成一次验证。
- [ ] 复盘、素材分析、知识库至少各打开一次。
- [ ] 客户知道数据备份位置和停止盯盘方式。

## 9. 出问题时的最小诊断信息

请先打开 **系统自检**，记录：

1. 总体状态和阻断项。
2. 应用版本、Python 版本、操作系统。
3. 发生问题的时间、页面和操作。
4. 是否刚重启、是否更换网络、是否重新登录千川。
5. 页面截图；不要发送 Token、Secret 或 Cookie。

如接口可访问，可导出诊断 JSON：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/system/doctor | ConvertTo-Json -Depth 8
```

## 10. 当前发布边界

这个版本可以作为**单客户试点 MVP**交付，但不能宣称已经是完整 SaaS：

- 尚未完成真实陌生客户的全新 Windows 独立安装验收。
- 尚未完成真实 Mac 从零安装验收；当前 macOS 支持以代码级自动化测试为主。
- 尚未完成多客户、多账户、远程访问和计费验证。
- 上线前仍需要一位非开发用户按本文独立走完一遍，并记录卡点。
