# Reflection 机制

## 目标

将直播运营 Agent 的“分析、判断、方案生成”改为：

```text
初稿 Draft → Critic 审查 → 必要时修订 Revise → 最终输出
```

数据读取、指标计算和操作执行不交给模型反思，仍由确定性程序负责。

## 适用范围

启用 Reflection：

- 直播运营助手对话
- ROI、GPM、消耗、素材、操作日志等分析
- 调整建议、执行方案和风险提示

不启用 Reflection：

- CDP / API 数据读取
- ROI、GPM、CPM 等指标公式计算
- 自检阈值判断
- 账户写操作

## 执行流程

### 1. Draft

模型根据以下上下文生成第一版回答：

- 当前投放策略
- 最新盯盘数据
- 复盘与素材分析
- 操作结果学习上下文
- 用户问题和图片

### 2. Critic

Critic 不重新回答，只审查草稿：

- 数字、时间、阈值是否有上下文依据
- 是否把现象误写成原因
- 是否混用综合营销 ROI、素材 ROI、支付 ROI 等口径
- 方案是否写清谁做、何时做、具体动作、成功标准和止损条件
- 是否违反只读边界
- 是否直接回答用户问题

Critic 返回：

```json
{
  "passed": false,
  "issues": ["缺少目标对比", "方案没有止损条件"],
  "must_revise": true
}
```

### 3. Revise

只有 Critic 未通过时才修订。修订规则：

- 逐条解决 Critic 指出的问题
- 不得新增上下文里没有的数字、时间、阈值或历史
- 没有数据时明确写“没读到”
- 保持原 JSON / 自然语言输出格式

### 4. Final validation

修订后重新解析输出：

- 校验 `kind`
- 校验消息非空
- 修订失败时回退到初稿，避免对话整体不可用

## 成本与安全边界

- 最多修订一次
- 自动分析通常调用模型 2 次；需要修订时最多 3 次
- Critic 或修订模型异常时回退初稿
- Reflection 只修改文本分析，不执行任何账户操作
- 最终建议仍必须人工确认

## 与确定性 Self-check 的区别

- `Reflection`：模型审查和重写分析内容
- `Self-check`：程序校验数据完整性、公式、漏斗、阈值和结论依据

两者同时存在：

```text
确定性数据校验门控
        +
LLM Reflection 审查修订
        +
操作结果反馈学习
```
